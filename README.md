# Dependence-Aware Physical PPA Design — code

Code accompanying *Dependence-Aware Physical PPA Design* (PJM case study). This
package contains **source code only**: no market data, no simulation outputs, no
figures. Everything the paper reports is regenerated by running the steps below.

Notebook outputs have been cleared, so every `.ipynb` here is source. Expect the
full pipeline to take many hours and tens of gigabytes of disk for intermediate
files.

## Contents

| Folder | What it does |
|---|---|
| `Input data and files/PJM Data/` | three notebooks that clean the raw PJM downloads |
| `process_and_realization/` | builds match files, fits marginals, estimates dependence, draws the scenario bank |
| `simulation_baseline/` | reference (no-channel) contract selection |
| `sensitivity_baseline/` | reference-set sensitivity cases |
| `simulation_mutation/` | channel-adjusted sample generation and risk-neutral selection |
| `simulation_mutation_averse/` | risk-averse counterparts |
| `figures_manuscript/` | rebuilds all eighteen manuscript and supplementary figures |

The only non-code files are
`sensitivity_baseline/Sensitivity_Cases_Verified_template.csv` (sensitivity case
definitions), `figures_manuscript/fig1_framework.tex` and
`figures_manuscript/fig2_simulation.tex` (the Figure 1 and Figure 2 diagram
sources).

The pipeline also needs two small workbooks that nothing in the code generates:
`Locational Information.xlsx` and `Seller_Buyer_Match_Table.xlsx`. They are not
shipped; **Step 0b below gives their full schema so you can rebuild them** from
the PJM downloads.

## Environment

Python 3.11 or later with `numpy`, `pandas`, `scipy`, `matplotlib`, `openpyxl`
and `jupyter`. Figures 1 and 2 additionally need `pdflatex` on the PATH (TeX Live or
MacTeX) with the `txfonts` package.

Scripts and notebooks resolve the package root automatically; no path editing is
required. Each mutation notebook has a commented `code_root_override` line if you
need to point it somewhere else. Run notebooks from their own folder.

# Step 0 — Obtain the PJM data

All inputs are public and free from **PJM Data Miner 2**,
<https://dataminer2.pjm.com/>. Browsing is open; bulk CSV export needs a free
PJM account. Confirm PJM's current terms of use before redistributing anything
you download.

**Set the date range on every download to 1 January 2025 00:00 through
1 January 2026 00:00 Eastern Prevailing Time (EPT), and export as CSV.** Every
feed returns both `datetime_beginning_utc` and `datetime_beginning_ept`; the
pipeline works in EPT. One node over this period is 8,761 hourly records.

Create the folders below and save each download exactly where shown.

### 1. Demand — feed "Hourly Load: Metered"

Whole RTO, no zone filter.

    Input data and files/PJM Data/Original Data/Demand/hourly_metered_load_all.csv

Verify the columns are:

    datetime_beginning_utc, datetime_beginning_ept, nerc_region, mkt_region,
    zone, load_area, mw, is_verified

This covers 22 transmission zones and 30 load areas. PJM's hierarchy is
NERC region -> market region -> transmission zone -> load area.

### 2 and 3. Generation — feeds "Solar Generation" and "Wind Generation"

All areas, downloaded separately.

    Input data and files/PJM Data/Original Data/Generation/hourly_solar_gen_all_area.csv
    Input data and files/PJM Data/Original Data/Generation/hourly_wind_gen_all_area.csv

Columns: `datetime_beginning_utc, datetime_beginning_ept, area,
solar_generation_mw` (resp. `wind_generation_mw`). Areas returned are MIDATL,
SOUTH, WEST, RFC, RTO and OTHER; **RFC and RTO are aggregates of the others, so
never sum across all six.** Solar values are occasionally slightly negative
(overnight station service); leave them as published.

### 4. Prices — feed "Real-Time Hourly LMPs", downloaded twice

Both price sets come from the same feed and differ only by pricing node type.
Confirm you have the real-time and not the day-ahead feed by checking for the
`_rt` suffix:

    datetime_beginning_utc, datetime_beginning_ept, pnode_id, pnode_name,
    voltage, equipment, type, zone, system_energy_price_rt, total_lmp_rt,
    congestion_price_rt, marginal_loss_price_rt, row_is_current, version_nbr

The pipeline uses `total_lmp_rt`.

**Seller side — set `Pricing Node Type = GEN`.** The unfiltered feed is too large
to export, so filter additionally by transmission zone and save one file per
zone, named `<market region>_<zone>.csv`:

    Input data and files/PJM Data/Original Data/Gen Side LMP/

Seven files are required, each holding every GEN node in its zone. The
representative seller node is selected later by
`process_and_realization/extract_match_PJM_data.py`, so do **not** pre-select one:

    MIDATL_AECO   MIDATL_BGE   MIDATL_DPL   SOUTH_DOM_CHESTER4
    WEST_ATSI     WEST_DAY     WEST_EKPC

**Buyer side — set `Pricing Node Type = LOAD`.** This filter alone returns an
exportable file. Save one file per buyer node, named `<zone>_<pnode name>.csv`:

    Input data and files/PJM Data/Original Data/Load Side LMP/

Eighteen files are required, one node each:

    AECO_ATCO    AEP_BELPRE   APS_POTTER    ATSI_02NASA   BGE_EASTPT
    COMED_102PALA  DEOK_EBEND  DOM_ACCA     DPL_AIREY     EKPC_SALTLICK
    JCPL_DOTWWHAR  METED_ALLEN  OVEC_DOEX530  PECO_ANGORA  PENELEC_ALLEGHEN
    PEPCO_BENNING  PPL_BERKS   PSEG_ALDENE

The seven seller zones and eighteen buyer nodes give the **126 seller--buyer
configurations** used throughout the paper. `Seller_Buyer_Match_Table.xlsx`
defines the pairing.

Data Miner 2 feed titles change occasionally; the column signatures above
identify each feed even if its title does not match.

# Step 0b — Rebuild the two workbooks

`extract_match_PJM_data.py` reads two Excel workbooks that no script generates.
Place both in `Input data and files/`. Everything in them is derivable from the
Step 0 downloads; the schemas below are exactly what the code expects.

## `Locational Information.xlsx`

One sheet, a header row and **21 data rows, one per PJM LMP transmission zone**:

| Column | Also accepted | Content |
|---|---|---|
| `Market Region (mkt_region)` | `Market_Region`, `Market Region` | the `mkt_region` value, e.g. `MIDATL` |
| `LMP Transmission Zone` | `LMP_Zone`, `LMP Zone`, `Zone` | the `zone` value in the LMP downloads, e.g. `AECO` |
| `Load Data zone` | `Load_Data_Zone`, `Load Zone`, `Load_Zone` | the `zone` value in the demand download, e.g. `AE` |
| `Load Data load_area (Matches to LMP Zone)` | `Load Data load_area`, `Load_Area_List`, `Load Area` | the `load_area` value(s) making up that LMP zone |
| `Notes` | — | free text, ignored by the code |

Every value comes from the Step 0 files: `mkt_region`, `zone` and `load_area` are
columns of `hourly_metered_load_all.csv`, and the LMP zone is the `zone` column of
the LMP downloads. Build the table by listing the distinct
`(mkt_region, zone, load_area)` triples in the demand file and pairing each with
the LMP zone that covers it.

**Where one LMP zone spans several load areas, put them in a single cell separated
by commas** — the code splits on commas and semicolons. For example the `DPL` LMP
zone maps to load zone `DPL` and load areas `DPLCO, EASTON, VMEU`.

## `Seller_Buyer_Match_Table.xlsx`

A sheet named **`All_Matches`** (failing that, the first sheet with a `match_id`
column is used), a header row and **126 data rows — every pairing of the 7 seller
zones with the 18 buyer nodes listed in Step 0**.

Five columns are required; the run fails without them:

| Column | Content |
|---|---|
| `match_id` | 1 to 126, assigned by the rule below |
| `seller_market_region` | market region of the seller zone, e.g. `MIDATL` |
| `buyer_zone` | the buyer's transmission zone, e.g. `AECO` |
| `seller_lmp_file` | seller LMP file name, e.g. `MIDATL_AECO.csv` |
| `buyer_lmp_file` | buyer LMP file name, e.g. `AECO_ATCO.csv` |

**Numbering.** Sort the sellers alphabetically by `seller_lmp_file` and the buyers
alphabetically by `buyer_lmp_file`, then iterate sellers in the outer loop:

    match_id = 18 * (seller position - 1) + buyer position

That gives seller `AECO` matches 1-18, `BGE` 19-36, `DPL` 37-54, `DOM` 55-72,
`ATSI` 73-90, `DAY` 91-108, `EKPC` 109-126. **Reproduce this ordering if you want
your match numbers to line up with the ones the paper reports.**

The authors' workbook carried further descriptive columns — `seller_area`,
`seller_zone`, `seller_corr_node`, `buyer_market_region`, `buyer_load_area`,
`buyer_load_area_count`, `buyer_load_area_values`, `demand_zone_reference`,
`buyer_corr_node`, `mapping_method`, `notes`, `ready_for_current_singular_code`,
`config_snippet` — plus `Sellers`, `Buyers`, `Summary` and `README` sheets. None is
required by the code. `buyer_load_area` is still worth carrying: where a buyer zone
covers several load areas its demand must be summed across them, the same
aggregation the locational workbook records. Four of the eighteen buyers are
multi-load-area; the rest map one to one.

**One naming trap.** PJM returns the ATSI buyer node as `02NASA` — digit zero,
digit two — and that is the spelling to use, in both the file name and the
workbook. It is easily mistyped as `OZNASA` (letter O, letter Z); if you meet that
spelling in any older copy of this project it is a transcription error, not a
second node. The run is self-consistent as long as the file name and the workbook
agree.

# Steps 1-7 — Run order

Run the steps in order. Each depends on the outputs of the previous one.

### Step 1. Clean the PJM downloads

In `Input data and files/PJM Data/`, run:

1. `Demand Processing.ipynb` -> `Demand/hourly_metered_load_all.csv`
2. `Generation Processing.ipynb` -> `Generation/hourly_total_gen_all_area.csv`
   (adds `total_generation_mw` as solar plus wind)
3. `LMP Processing.ipynb` -> `Gen_LMP/` and `Demand_LMP/`

### Step 2. Build the scenario bank

In `process_and_realization/`, run in this order:

1. `extract_match_PJM_data.py` — assembles the 126 match files from the cleaned
   PJM series and the two workbooks built in Step 0b
   -> `Input data and files/Match files of original data/`
2. `select_marginals.py` — fits the per-variable marginal distributions
   -> `Input data and files/Marginal_Fit/`
3. `extract_correlations.py` — estimates the copula correlation banks
   -> `Input data and files/Correlation/`
4. `sample_realizations.py` — draws the reference scenario bank
   -> `Input data and files/Simplified baseline realized samples/`

`add_columns_quick.py`, `add_metadata_to_samples.py`,
`inspect_historical_skewness.py` and `prepare_scenario_paths_for_validation.py`
are optional metadata and diagnostic utilities; none is required to reproduce the
paper's results.

### Step 3. Reference contract selection

In `simulation_baseline/`:

1. `simulation (no mutation, verified).ipynb` — the reference selection
   -> `Output files (Risk Neutral, No Mutation, Verified)/`
2. `plot_result_no_mutation.ipynb` and `plot_FE (no mutation).ipynb` — baseline
   plot tables

`simulation (no mutation, global search).ipynb` and
`Compare_Verified_vs_Exact_Global_Search.ipynb` are an optional check that grid
enumeration reaches the same optimum as an exact search. They are not needed for
any reported number.

### Step 4. Sensitivity cases

In `sensitivity_baseline/`, edit `Sensitivity_Cases_Verified_template.csv` only
if the case definitions change, then run:

1. `1_Sensitivity_Run_revised_contract_period.ipynb`
   -> `Output files (Sensitivity, No Mutation, Verified)/`
2. `3_Sensitivity_Summarize.ipynb`
3. `2_1_Sensitivity_Plot.ipynb` and `2_2_Sensitivity_Plot_grouped.ipynb`

`verified_simulation_engine.py` holds the shared search logic these notebooks
import. `run_sensitivity_parallel_codex_signed_prices.py` is a parallel runner
for the same cases.

### Step 5. Dependence channels, risk-neutral

In `simulation_mutation/`:

1. `mutation_sample_generation.ipynb` — builds the channel-adjusted scenario sets
   by rank reassignment -> `mutation_samples/` (large; this is the bulk of the
   disk requirement)
2. `simulation_mutation.ipynb` — re-solves the design problem on every channel
   case -> `Output files (Risk Neutral, Mutation, Verified)/`
3. `plot_contract_price_volume_utility_minimal_update.ipynb`
4. `plot_mutation_choice_evolution.ipynb`
5. `plot_mutation_fe_comparison.ipynb`

`simulation_mutation_from_notebook.py` is the exported script form of step 5.2,
for running outside Jupyter.

### Step 6. Dependence channels, risk-averse

In `simulation_mutation_averse/`, reusing `mutation_samples/` from step 5.1:

1. `simulation_mutation_risk_averse.ipynb`
   -> `Output files (Risk Averse, Mutation, Verified)/`
2. `risk_averse_mutation_01_aggregate_analysis.ipynb`
3. `risk_averse_mutation_02_choice_evolution_maps.ipynb`
4. `risk_averse_mutation_03_fe_distribution_diagnostics.ipynb`

`simulation_mutation_risk_averse_from_notebook.py` is the exported script form of
step 6.1.

### Step 7. Rebuild the figures

From `figures_manuscript/`:

    python make_all_figures.py <output_dir>

This writes all eighteen figures under the exact file names the manuscript's
`\includegraphics` keys use, so the output directory can be copied straight over
the manuscript's `images/` folder.

| Figure | Producer |
|---|---|
| 1 | `build_fig1_framework.py` (needs `pdflatex`; the diagram source is `fig1_framework.tex`) |
| 2 | `build_fig2_simulation.py` (needs `pdflatex`; the diagram source is `fig2_simulation.tex`) |
| 3-6 | `build_figs_2_3_5_redesign.py` (reads the journal tables written by steps 5 and 6) |
| 7, 8, A4-A10 | `build_print_figures.py` |
| A1-A3 | `generate_figures_A1_A3_print.py` |

The three plotting producers import `figure_palette.py`, which holds the single colour
palette and the shared typography and axis style, so a change there reaches every
figure at once. `build_figs_2_3_5_redesign.py --verify` reprints the selection
shares, medians and quartiles quoted in Sections 5.2 and 5.3 of the manuscript
next to the values the figures are drawn from.

`rebuild_figs_2_5_labels.py` produced the earlier version of Figures 3-6 (numbered 2-5 at the time) by
driving `simulation_mutation/plot_contract_price_volume_utility_minimal_update.ipynb`
read-only. It is superseded by `build_figs_2_3_5_redesign.py`, is no longer called
by `make_all_figures.py`, and is kept only as the record of how those figures were
made before the redesign.

## Notes

**Buyer procurement price.** `sample_realizations.py` and
`extract_match_PJM_data.py` build the buyer procurement price from the resale
price as

    buyer_lmp_in = buyer_lmp_out + X * abs(buyer_lmp_out),
    X ~ scaled Beta(2,3) on [0.5, 2.0]

which is the markup equation in the paper. The nonnegative markup keeps
procurement weakly above resale in every hour, including hours of negative
price. Rank reassignment in step 5.1 carries each hour's markup ratio to its
destination hour, which can produce a signed spread in a small share of hours;
the paper's convexity result is invoked only under its stated nonnegative-spread
condition, while the evaluation permits signed spreads.

**Naming.** `FE` in file and column names is the **seller exposure index** of the
paper. The abbreviation does not appear in the manuscript.

**Reproducibility.** The scenario bank is drawn with fixed seeds recorded in the
run-summary JSON that `sample_realizations.py` writes alongside its output. A
rerun of steps 2-6 reproduces the reported selections; expected buyer exposure
depends on the markup draw, so state the draw when comparing exposure levels
across runs.
